🧪 Tree + Virtual / Infinite Scroll

Test view for combining tree mode with high-volume scrolling primitives. Both combinations are technically supported but have UX trade-offs — this page exists so you can poke them.

1. Tree + Virtual Scroll

Full tree (… rows, 3 levels deep) loaded once, virtual scroll renders only the visible rows. Toggle expand/collapse and watch render count update.

Visible: 0 rows
What to look for:
  • Smooth scroll through all rows without slowdown
  • Toggling a parent collapses/expands instantly even with thousands of descendants
  • Row heights stay consistent (no jitter from the tree wrapper)
  • Frozen / sticky headers still pin correctly

2. Tree + Infinite Scroll

"Server" returns full subtrees (one root + all its descendants) in batches. Each batch appends to the bottom of the items array, so caller-controlled append-order works cleanly with treeDataSorted: true.

Loaded: 0 rows Has more: yes Loading…
What to look for:
  • Scroll to the bottom — new root subtrees should append seamlessly
  • Already-expanded state of earlier rows is preserved across loads
  • Loading indicator appears during the simulated 300ms server fetch
  • When the dataset is exhausted, "Has more" flips to no and loading stops

Caveat: infinite scroll fits "more siblings appended at the bottom" semantics. For "load children of an expanded node on demand", we'd need a separate per-node lazy-load callback — not implemented today.
