🔎 Product Search (Custom Editor)

Dialog-based custom editor with search, keyboard navigation, and cached display value

Interactive Demo

The Product column stores a product id but displays the product name. Press F2, Space, or double-click a cell in that column to open the search dialog. Type to filter, use ↑/↓ to navigate, Enter to select, Esc to cancel.

Event Log:
[Ready] Edit the Product column to open the search dialog.

How it works

  1. The cell stores a productId (number).
  2. formatCallback looks up the product in the catalog and returns its name for display.
  3. cellEditCallback opens a modal search dialog instead of inline editing.
  4. When the user picks a product, context.commit(id) saves the id and the grid re-renders the name automatically.
  5. Sibling columns (SKU, Price) also read from the catalog using the same id.

Column definition

{
    field: 'productId',
    title: 'Product',
    editor: 'custom',
    formatCallback: (id) => {
        const p = catalog.find(p => p.id === id)
        return p ? p.name : '—'
    },
    cellEditCallback: (context) => {
        openProductSearch(context, catalog)
        // dialog calls context.commit(product.id)
        // or context.cancel()
    }
}

Notes

  • Single source of truth: the row only stores the id — all other product fields are derived at render time.
  • Keyboard-first: the dialog listens for arrows, Enter, and Escape so it feels native in the grid flow.
  • Commit vs cancel: always call exactly one of context.commit(value) or context.cancel() — the grid stays in edit state until you do.
  • Focus return: after commit/cancel, the grid moves focus back to the edited cell automatically.
  • Refreshing dependent cells: the grid re-renders only the cell that was edited. When other columns derive their display from the edited field (SKU/Category/Price/Total here), reassign grid.items = [...rows] in onrowchange to force a full re-render. If you instead store real product fields on the row, you don't need this.
